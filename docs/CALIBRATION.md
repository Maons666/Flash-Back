# 国际服 PC 校准说明

适用程序 v0.10、参考补丁 13.09。官方演示视频已收录，但尚未取得当前补丁下、测量条件一致的独立游戏录像。软件测试只证明模拟执行了配置的规则，不能证明与真实游戏的误差为零。

## 先确认测量口径

用当前版本自定义房的接收闪光者视角录制，固定分辨率、视野、帧率、画面亮度和同一处爆点。建议固定帧率 240 FPS（或设备能稳定记录的 120 FPS）；不要把补帧或变帧率视频按固定帧号直接换算。不要改变鼠标 DPI 和游戏灵敏度：当前为 1600 × 0.175。

每组重复至少 5 次，记录中位数与最大/最小值，不把单次录像的读帧误差当作技能差异。保留原片、游戏版本、录像帧率、网络条件、站位距离、水平/垂直视角及起止帧编号。时间用 `(终止帧 - 起始帧) / FPS`。240 FPS 每帧约 4.17ms，两端各错一帧时最坏误差约 ±8.33ms；这还不包含显示、采集和网络延迟。

| 参数 | 取帧口径 |
| --- | --- |
| Phoenix / KAY/O / Hush 引信 | 投射物释放帧至爆开帧，区分上手、下手、触碰和转向 |
| Breach 前摇 | 墙面提示首次显现至爆开，不包含另一侧施放者的出手动画 |
| Yoru 闪球前摇 | 首次反弹激活帧至爆开帧 |
| Yoru 分身 | 被射击触发帧至爆开帧 |
| Skye | 飞行至激活单独计时，再测激活至爆开的 0.3s；不要把两段合并填写 |
| Reyna | 分别测到位至生效、到位至消失；“眼球总存续”包含前摇 |
| Gekko | 部署形成、0.35s 锁定、电浆飞行、遮挡、渐隐分别记录 |
| 受闪表 | 固定爆点距离和视角，统一测量爆开至画面完全恢复；不要混入“全白阶段”时长 |

官方公告的“最大闪光时长”和录像“完全恢复时间”可能不是同一阶段边界。若两者不同，先保留两套原始记录，不要为了凑公告数字删掉渐隐帧。

## 应用到程序

1. 在左侧选择特工和投法，打开“实测校准与来源”。
2. 填写时序值及测量来源备注。输入框不是新的官方值；应用后显示为“用户校准”。
3. 需要替换角度衰减时，展开实测表。每行填写 `角度,距离,致盲总时长`，单位为度、米、秒。不能填猜测值或空值。
4. 建议按 0°、30°、45°、60°、90°、120°、150°、180°，分别在 5m、10m、20m 测量。每个距离必须有 0°、180°，各距离使用相同角度网格。也可从两个端点开始，但稀疏插值不能代表真实曲线形状。
5. 点击“应用校准”。“导出校准文件”保存当前输入，“导入并应用”验证补丁、平台、投法、有限数值、端点和网格。恢复默认只清除当前投法；Hush 会同时恢复其共用引信/时长基线。

校准表仅在已测距离范围内生效。范围之外不会伪造外推，仍使用近似模型；CSV 的 `exposureModel=outside-samples` 标识这种情况。`user-samples` 仅表示用了用户表，不是 Riot 认可。视线完全遮挡时，普通闪光仍判定为 0，不受用户表覆盖。

历史 CSV 同时记录版本、程序修订、距离、模型与来源备注。新记录的 `approximate` 始终为 true，因为轨迹、视觉、声音与角色运动仍有未校准部分。旧版记录不追溯伪造来源，不宜与修正后的反应计时直接混算。

## 飞行与反弹参数

选择 KAY/O、Skye、Yoru、Hush 或 Gekko 后，校准窗口中有「飞行与弹道校准」。速度单位为本训练场的 m/s，重力为 m/s²，反弹比例为法线反射后保留的速度比例。改变速度不会移动出手点；Skye 会沿同一路径更快或更慢推进，不会在结束时强行吸附到原先终点。Skye 不使用重力或反弹系数。

| 默认参数 | 速度 | 重力 | 反弹比例 | 证据边界 |
| --- | --- | --- | --- | --- |
| KAY/O 上手 | 18 | 2.94 | 0.6 | 速度参考社区投射物资料；重力由 0.3×9.8 换算，反弹为训练估计 |
| KAY/O 下手 | 6.3 | 2.94 | 0.6 | 同上；不是 Riot 公开引擎常量 |
| Skye | 18 | 0 | 0 | 速度参考社区 Guiding Light 资料；操控曲率为场景设计 |
| Yoru | 29 | 4.41 | 1 | 当前训练基线，仍需验证；首次反弹后不再施加重力 |
| Hush | 18 | 2.94 | 0 | 当前训练基线，触碰爆开；转向后直飞 |
| Gekko | 18 | 2.94 | 0.5 | 当前训练基线；部署完成后进入悬停锁定 |

社区参考：[投射物分类](https://wiki.playvalorant.com/en-us/Projectile)、[Guiding Light](https://wiki.playvalorant.com/en-us/Guiding_Light)。它们不是官方精确性承诺。数值集中在 `src/trajectories.js`，运行时可由用户校准覆盖。

测速度时记录同一投射物通过两个已知距离标记的帧号，按 `距离 / 时间` 求速度；先校准世界比例，再校准运动。重力应由多个时间点的高度拟合，不能只靠一个落点。反弹需分别记录碰撞前后速度，并把墙面与地面、入射角度分开测量。转弯鸟用路线实际长度而非起终点直线距离计算速度。

JSON 的可选 `motion` 字段接受 `speed`、`gravity`、`restitution`。参数保存在当前特工/投法下；原有 schema 1 时序和衰减文件仍然兼容。导出时保留来源备注；填入估计值时应在备注中说明，不能把默认值导出后称为实测结果。

## 当前验证覆盖与剩余工作

回归测试覆盖 30/60/120/144/240 FPS 下的配置引信、非整步定时、碰撞反射、Skye 分阶段、矩形视野、Reyna 清除效果、Dizzy 身体可见性和已发射电浆、校准持久化与输入验证。已知定时事件按绝对事件边界推进，运动子步不超过 4.17ms；显示仍受实际刷新率和系统调度限制。

后续最有价值的数据是 Hush 的实测时序，以及每种闪光正面、侧面、背面的恢复时间和视觉渐隐曲线。仍待单独测量：投掷初速度/重力/反弹损耗、全白与渐隐分配、声音频谱与触发点、移动加减速、视角高度、精确命中体积。单纯多写小数位或把“待实测”改成“精确”不会提高一致性。
